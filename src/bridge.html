How it works

A git forge that hands work to an AI agent

People on a self-hosted git forge ask for work where they already are. They mention the agent in an issue or a pull request and the answer comes back in the same thread, as a comment or a pull request. It runs unattended on one host and spreads the work over several subscription accounts.

Built and in daily use. The code isn't public: this is a description written for this site.

The pipeline

From a mention to a pull request

  1. Mention@claude in an issue or PR, or a new issue in an opted-in repository.
  2. WebhookSignature verified, deliveries de-duplicated, the bot's own comments ignored.
  3. Who may askAn allowlist, the repo's collaborators (checked live) or anyone. A failed check refuses.
  4. ModeReview, architect, security, triage, implement… from a verb, or from a classifier that says what it assumed.
  5. QueueWorkers behind a STOP switch; work held back by limits waits with a not-before time instead of being dropped.
  6. Isolated runA fresh checkout, the agent headless with a tool allowlist, a turn cap, a timeout and a budget; secrets stripped.
  7. Quality passesThe author, then reviewers with fresh context, then repair rounds while the defect count still falls.
  8. AnswerA comment and/or a PR on a claude/* branch, never straight to the default branch.

Safety and limits

What keeps it in bounds

  • Usage gating. It reads the 5-hour and 7-day usage windows, defers jobs above a threshold and resumes them after the reset. Work it starts on its own has tighter ceilings, by day and night; people are not throttled that way.
  • A budget per issue. Every turn counts against the issue, added after one issue burned through its money while staying under every per-run cap.
  • Account pools. Calls go through a multi-account proxy that can move a session between accounts at a limit, and workloads are split into pools so one cannot eat everyone's window.
  • Checkpoints. Near a limit, the working tree is snapshotted to a work-in-progress branch every few minutes, so a run killed by a limit or a restart resumes instead of starting over.
  • Visibility that fails closed. A status endpoint and page, metrics and a run history; a separate portal streams runs live and shows each person only what the forge lets them see with their own token.

For a team

What it gives a team

Anyone who can file a ticket can hand off a review, a triage or an implementation without installing anything or learning commands. Results arrive in the normal review flow, cost and safety are enforced in one place, and work survives limits and restarts, so long runs can go overnight.
