About this mock-up

A system I built and run: it serves several large language models from one machine with four GPUs. The real one isn't public, so this page is a mock-up of it, written from scratch for this site. Everything here runs in your browser on made-up data, and none of it is the real code.

What it does

Each model runs as its own vLLM engine in a container, and clients see one OpenAI-compatible endpoint: they name a model in model and a stopped one starts on demand. An operator decides which card a model lives on, how long a context it serves and whether it may be stopped to make room. External jobs book a model for a time window and can count on the memory being there.

How it works

  • Two small services. A manager drives the containers; a gateway is the only client of the engines.
  • Ready from the log, not from probes. The manager follows an engine's log until it says it is up, and reads its measured memory from the same lines.
  • Admission by measured budgets. Each card is a budget of memory floors against a 95% ceiling, one start at a time. Free memory is read only to refuse a start, never to admit one.
  • Eviction that knows what it may stop. Only idle on-demand models go, least recently used first; pinned and booked ones never. A start that does not fit even then is refused before anything stops.
  • A gateway that hides cold starts. It keeps the client's stream alive with comment keepalives while the model loads, then passes the engine's answer through untouched.
  • One planner for every promise. Bookings, pins, edits and deletes go through the same interval check, and a refusal names the booking in the way.

What I like about it

  • Two starts can never both see free memory and both run out: admission trusts measured profiles, with an estimate only until the first measurement.
  • A booking admitted on an estimate turns unfulfillable as soon as a measurement disproves it, with the reason, instead of failing at its start time.
  • The client never notices a model being loaded, and the stream it gets is the engine's own.

What to try

  • Start model-b, then model-a-moe on the same card: the first is evicted to make room.
  • Start qwen2.5-7b: its card is full and nothing there may be stopped, so it is refused.
  • In the Playground, send a prompt to a stopped model and watch the cold start.
  • Pin model-c: a booking stands in the way.

The models are public ones or placeholders, the host and addresses are invented, and the answers are canned. "Reset demo" puts everything back.
