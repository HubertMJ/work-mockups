Flota: a fleet of AI coding sessions for one project

A project manager session hands out work; section sessions do it, each in its own terminal, addressed by name. A guard with no model watches the account's usage limits, and the manager is technically unable to do the work itself. Managers of different fleets, even under different Linux users, write to each other, and one supervisor session gathers every fleet's questions for the owner.

Built and used on a real project, then rewritten from scratch as a general tool. The source goes public once it has been tested on more projects; until then this page describes it, with made-up fleets.

How it works

Small parts, state in files

  • Interactive start. flota opens a menu; flota new asks for the repository, the sections and their scope, the limits and the models, and writes the project.
  • Roles, not chats. Every session gets its role (manager, section or the single merger) and its row of the routing table as part of its system prompt.
  • Orders and reports. The manager sends numbered orders; sections answer with a report, decisions go to a log before they are acted on, and everything lives in files, so a restart loses nothing.
  • One merger. Only one session merges, so pull requests land in order, rebased, with migrations numbered and CI green.
  • Limits enforced in three steps. Below the start threshold nothing new starts; at the pause threshold the guard tells every session to commit and stop; at the hard one it closes the sections. It costs no tokens.
  • A manager that cannot code. A tool hook refuses edits outside the fleet's own files, any shell that writes, and subagents; the reason goes back to the model with “give it to a section”.
  • Managers talk across fleets. flota channel send drops a message in the other manager's mailbox in a spool on the host, and a registry says who is who. Only the sender's Linux user can write to its slot in a mailbox, so no fleet can pose as another; sections never use the channel.
  • A courier that never types the message. Each fleet runs a courier with no model. When mail comes in and the manager sits idle (no dialog open, the owner not typing), it types one line into the manager's window: who wants to reach it. The manager reads the message itself with flota channel receive, as data, not as an order.
  • MultiAsk. One supervisor session where the managers of all fleets put their questions to the owner, so many fleets running at once are watched from one window. A fleet's owner turns it on for that fleet; the answer goes back over the channel, and the manager takes it as the owner's only when it really comes from MultiAsk.
  • Survives reboots. Sessions are resumed by their saved id, and flota restore brings back the registered fleet after the host restarts.
